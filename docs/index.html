PMS Integration API

This API allows PMS systems to pull reservation sync events from RevenueTales, retrieve reservation payloads, and confirm successful import.

Most PMS integrations should use:

GET /reservations/pending/full for pulling data + POST /reservations/sync/bulk for acknowledgements.

Base URL and Authentication

Base URL

https://travelagents-pms-integration-670805103288.europe-west1.run.app/api/v1

Authentication header (required on every request)

Authorization: Bearer <API_KEY>
  • API key must be active.
  • API key is scoped to one PMS and one hotel.
  • Request hotel_id must match the key hotel scope.

Core Concepts

  • booking_id: RevenueTales internal booking identifier.
  • event_id: unique sync event identifier; required for acknowledgements.
  • sync_type: NEW, MOD, or CL.
  • sync_status: PENDING, ACKNOWLEDGED, FAILED, BLOCKED.
  • Idempotency: confirming the same event again is safe.

Sync Workflow (Recommended)

1) Pull pending events with full payload
   GET /reservations/pending/full

2) Import each reservation to PMS

3) Acknowledge imported events
   POST /reservations/sync/bulk

Fallback option:
- Use GET /reservations/pending + GET /reservations/{booking_id} + POST /reservations/{booking_id}/sync

Failure Handling

Important: sync endpoints in this API only accept status=success. Failure reporting is not sent via POST in the current version.

If a pull request fails (GET /reservations/pending or GET /reservations/pending/full):

  • Do not acknowledge any events.
  • Retry the same request (same parameters) with backoff.
  • If repeated failures continue, share the API error response with RevenueTales support, including request_id.

If PMS import fails after a successful pull:

  • Do not call sync confirmation for that event yet.
  • Keep the event in your retry queue and attempt import again.
  • Call sync confirmation only after successful PMS import.

All Endpoints

  • GET /api/v1/reservations/pending - pending events summary
  • GET /api/v1/reservations/pending/full - pending events with full reservation payload
  • GET /api/v1/reservations/{booking_id} - full details for one booking
  • POST /api/v1/reservations/{booking_id}/sync - acknowledge one sync event
  • POST /api/v1/reservations/sync/bulk - acknowledge many sync events in one request

GET /reservations/pending

Returns pending events only (lightweight list), without full reservation payload.

Required query parameters:

  • hotel_id (string)

Optional query parameters:

  • limit (int, default 100, max 500)
  • page_token (string, for next page)
curl -X GET "https://travelagents-pms-integration-670805103288.europe-west1.run.app/api/v1/reservations/pending?hotel_id=9b767697-4f60-4b78-b387-b6f69ccdb7bc&limit=100" \
  -H "Authorization: Bearer <API_KEY>"
import requests

url = "https://travelagents-pms-integration-670805103288.europe-west1.run.app/api/v1/reservations/pending"
headers = {"Authorization": "Bearer "}
params = {"hotel_id": "9b767697-4f60-4b78-b387-b6f69ccdb7bc", "limit": 100}

response = requests.get(url, headers=headers, params=params, timeout=30)
print(response.status_code)
print(response.json())

url.searchParams.set("hotel_id", "9b767697-4f60-4b78-b387-b6f69ccdb7bc");
url.searchParams.set("limit", "100");

const response = await fetch(url, { headers: { Authorization: "Bearer " } });
console.log(response.status);
console.log(await response.json());

How to get the next set of reservations

  1. Check if next_page_token exists in the response.
  2. If it exists, call the same endpoint again with the same hotel_id and limit, plus page_token.
  3. Repeat until next_page_token is not present.

Important: always keep the same hotel_id and limit when requesting the next page with page_token.

POST /reservations/{booking_id}/sync

Acknowledges one event after successful PMS import.

When to use this endpoint: use for single-item fallback, debugging, or manual retries. For normal PMS operation, prefer POST /reservations/sync/bulk.

Path parameters:

  • booking_id (string, required)

Request body fields:

  • event_id (string, required)
  • status (string, required, must be success)
  • pms_reference (string, optional)
curl -X POST "https://travelagents-pms-integration-670805103288.europe-west1.run.app/api/v1/reservations/d2f0ee30-f7aa-4d39-9df9-f181ec4cf5f9/sync" \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "event_id": "e4e4b3bc-4d2a-4b41-b8b8-69f4f5f51309",
    "status": "success",
    "pms_reference": "PMS_NAME"
  }'

POST /reservations/sync/bulk

Acknowledges many events in one request (recommended for PMS batch processing).

Recommendation: this should be your default acknowledgement endpoint in production.

Request body fields:

  • hotel_id (string, required)
  • items (array, required, max 100)
  • Each item requires: booking_id, event_id, status=success
  • Each item may include: pms_reference

Error Responses

Standard error format:

{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing or invalid API key",
    "request_id": "req_..."
  }
}

Status codes:

  • 401 missing, invalid, or inactive API key
  • 403 hotel is not authorized for the key
  • 404 reservation or event not found
  • 422 validation error
  • 500 internal server error

Go Live Checklist

  • Use test key and verify authentication first.
  • Verify one full cycle using /pending/full then /sync/bulk.
  • Confirm pagination loop stops when next_page_token is absent.
  • Confirm idempotent behavior by retrying the same sync confirmation payload.
  • Monitor error rates and request latency.
