PMS Integration API (v1)

This API allows PMS partners to pull reservations from RevenueTales and confirm successful import. Integration is pull-based and designed for polling every 5 minutes.

Base URL

https://<YOUR_PMS_API_HOST>/api/v1

Replace <YOUR_PMS_API_HOST> with the deployed Cloud Function host.

Quickstart

  1. Get your API key from RevenueTales onboarding team.
  2. Poll pending reservations.
  3. Fetch reservation details for each booking.
  4. Import booking into PMS.
  5. Confirm sync with /reservations/{booking_id}/sync.
curl -X GET "https://<YOUR_PMS_API_HOST>/api/v1/reservations/pending?hotel_id=9b767697-4f60-4b78-b387-b6f69ccdb7bc" \
  -H "Authorization: Bearer <API_KEY>"

Authentication and Authorization

  • Use header: Authorization: Bearer <API_KEY>.
  • API key must be active.
  • Each key is scoped to one hotel and one PMS partner.
  • All requests are validated against key hotel_id scope.

Sync Workflow

1) GET /reservations/pending
2) For each event: GET /reservations/{booking_id}
3) Import into PMS
4) POST /reservations/{booking_id}/sync

The sync confirmation endpoint is idempotent. If you retry confirmation for the same event, the API safely returns success without duplicate processing.

Error Handling

All errors follow one structure:

{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Missing or invalid API key",
    "request_id": "req_..."
  }
}
  • 401: missing, invalid, or inactive API key
  • 403: hotel is outside key scope
  • 404: reservation/event not found
  • 409: invalid state transition
  • 422: request validation error
  • 500: internal server error

Data Models

  • sync_type: NEW, MOD, CL
  • sync_status: PENDING, ACKNOWLEDGED, FAILED, BLOCKED
  • board_id: derived from normalized board type map
